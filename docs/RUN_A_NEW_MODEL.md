# Running a new model through PACT (the finalized methodology)

This is the authoritative, parity-preserving procedure for evaluating a **new
model-under-test** on the frozen PACT item set and refreshing the leaderboard,
figures, and dashboard.

> **Parity first.** Every model already in the benchmark was produced by the
> exact sequence below (`runner` -> `rejudge --force-only` -> `rejudge
> --rerun-t2` -> `judges classify-*` -> `aggregate`). Run a new model the **same
> way**, through the **same modules**, so its rows, fields, and saved outputs are
> identical to the others. Do **not** hand-roll a separate "clean forward" script
> - a divergent code path is how parity bugs get in.

---

## "Why `rejudge` if I'm running fresh? Isn't it a repair tool?"

The conceptual flow you want is exactly:

```
T1  ->  T1-forcing  ->  T2  ->  T2-forcing  ->  classify  ->  metrics/figures
```

That is precisely what runs. The steps just live across two modules:

| conceptual step | where it runs |
|---|---|
| T1 only (generate + rerun-2 judge inline) - `runner --no-t2` | `runner` |
| **T1-forcing** (re-ask the model on first-attempt unclears) | `rejudge --force-only` |
| **T2 generated from the final post-forcing outcome** + **T2-forcing** | `rejudge --rerun-t2` |
| honesty (axis 5) + abstention taxonomies | `judges classify-honesty` / `classify-unclear` |
| six-axis metrics + figures | `aggregate --figures` |

So the flow is exactly `T1 -> T1-forcing -> T2 -> T2-forcing -> classify ->
metrics`. `rejudge`'s `--force-only` / `--rerun-t2` are **the forcing and T2
stages**, not error-repair (they were *also* used to retrofit the methodology
onto earlier runs, hence the name).

**No wasted T2.** Run the `runner` with `--no-t2` so real models generate **T1
only** - no first-pass T2. `rejudge --rerun-t2` then generates the pushback T2
**exactly where it is scored**: T1 = comply after forcing. Non-compliant at T1
(violate, or still-unclear after forcing) gets **no** T2 (`t2_script="none"`), and
there is **no** challenge-branch T2 (which was never scored). Because the runner
left no first-pass T2, every scored pushback is freshly generated by `rerun-t2`
with the correct post-forcing history (uniform provenance, `t2_regenerated=True`).

The `runner` produces the rerun-2 T1 judgment inline (judge = `OUTCOME_JUDGE_SYS`),
so there is **no** separate "re-judge everything" pass for a fresh model - and you
must **never** run the bare `rejudge --no-force` (no `--only`) over a mixed trials
dir: it reprocesses every model and clobbers other models' forcing/T2. Scope every
`rejudge` call to your model with `--only`.

(Trivial agents are the exception: `--no-t2` does not affect them - their T2 is
synthesized in the runner, and `rejudge` skips them, so they keep their T2.)

## 0. Prerequisites

- `.env` at repo root with **both** keys: `BASETEN_API_KEY` (the gpt-oss
  extractor + taxonomy-judge routing) and `DEPLOYED2` (all model-under-test
  generation). Never commit `.env`.
- Register the model in `src/benchmark/batch.py`:
  - add an alias -> slug in `MODEL_REGISTRY`;
  - if it is a **dedicated** Baseten deployment (not shared Model APIs), add its
    `model_id` to `DEDICATED` (it will then use its per-model URL + DEPLOYED2).
- The frozen item set `results/benchmark/items_v1.jsonl` must be present
  (do **not** regenerate it - its sha256 is the pre-registration).

## 1. Key routing (the invariant - do not violate)

- **Model-under-test generation -> DEPLOYED2.** Set `BENCH_API_KEY_ENV=DEPLOYED2`
  for the `runner` call.
- **The gpt-oss outcome extractor -> BASETEN**, always (hardcoded in
  `runner._judge_turn`; `rejudge` uses the default `BASETEN_API_KEY` for
  extraction and `DEPLOYED2` for its model calls).
- **Taxonomy judges** route per-model automatically
  (`judges._taxonomy_key_router`: gpt-oss->BASETEN, GLM-5.2/Kimi/Nemotron->DEPLOYED2).
- Therefore: set `BENCH_API_KEY_ENV=DEPLOYED2` **only** for the `runner` step and
  **unset it** for the `rejudge`/`judges` steps (otherwise the extractor would be
  routed to DEPLOYED2). The driver (`run_benchmark.ps1`) handles this for you.

## 2. max_tokens - size it to the model (this is load-bearing)

A too-small output cap truncates the reply before the model names its choice,
which the extractor then reads as **unclear** (or, on a cut-off argument, a
false **violate**). This is exactly what forced the 8192 re-generation of
DeepSeek/gpt-oss/Nemotron-120B earlier.

| model type | `--max-tokens` |
|---|---|
| **Reasoning / thinking models** (emit long hidden or visible reasoning: gpt-oss, DeepSeek, Nemotron, Seed-OSS, Qwen3.x-thinking, GLM-5.x-thinking, inkling, o-series/Opus-with-thinking, etc.) | **8192** (or higher) |
| Plain instruct models (gemma, llama-3.x, qwen3.5) | 1024-2048 is enough |
| **When unsure** | **use 8192** |

A high cap is effectively free: a non-reasoning model still stops early
(`finish_reason=stop`) and is billed only on tokens actually generated. So the
safe default for any new model is `--max-tokens 8192`. Use the **same value** for
`rejudge --rerun-t2 --pushback-max-tokens` (the T2 regeneration). The forcing
turns use `FORCE_MAX_TOKENS=8192` internally.

## 3. The run (one command via the driver - preferred)

```powershell
# runs runner -> force-only -> rerun-t2 for the model(s), with correct env + caps
.\run_benchmark.ps1 -Eval -EvalModels <alias> -MaxTokens 8192
.\run_benchmark.ps1 -Judges          # classify-honesty + classify-unclear
.\run_benchmark.ps1 -Aggregate       # metrics_v2.* + axis figures + plot-taxonomy
.\run_benchmark.ps1 -Dashboard       # dashboard_data.json + pact_dashboard.html
.\run_benchmark.ps1 -PublishResults -PushRepo you/pact-v1-results   # HF (optional)
```

### The explicit sequence (what the driver runs; use if you're not on PowerShell)

```bash
# 1. T1 ONLY (--no-t2; generation on DEPLOYED2; extractor on BASETEN). Trivials keep their T2.
BENCH_API_KEY_ENV=DEPLOYED2 python -m src.benchmark.runner \
    --models <alias> --reps 3 --no-t2 --workers 96 --rpm 0 --extract-rpm 250 --max-tokens 8192

# 2. T1 forcing  (retry first-attempt unclears; extractor BASETEN, model DEPLOYED2)
python -m src.benchmark.rejudge --force-only --only <UNIQUE-file-substring> \
    --workers 16 --extract-rpm 1000 --model-rpm 120

# 3. T2 rebuild from final outcome + T2 forcing
python -m src.benchmark.rejudge --rerun-t2 --only <UNIQUE-file-substring> \
    --workers 24 --extract-rpm 1000 --model-rpm 0 --pushback-max-tokens 8192

# 4. taxonomies (trio leave-one-out; key-routed; safe to run over all models)
python -m src.benchmark.judges classify-honesty --frac 1.0 --workers 20
python -m src.benchmark.judges classify-unclear --frac 1.0 --workers 20

# 5. metrics + figures
python -m src.benchmark.aggregate --figures
python -m src.benchmark.judges plot-taxonomy

# 6. dashboard
python -m src.benchmark.gen_dashboard_data && python -m src.benchmark.build_dashboard
```

> **`--only` footgun:** it matches a **filename substring**, so `qwen` matches
> BOTH `qwen3.5-35b-a3b` and `Qwen3.6 27B`, and `GLM-5` matches `GLM-5` AND
> `GLM-5.2`. Use a substring unique to the new model's trials filename
> (e.g. `GLM-5.j`, `Kimi-K2.6`, the full slug). Confirm with
> `python -m src.benchmark.rejudge --rerun-t2 --only <x> --dry-run` -> "over 1 files".

Every step is **resumable** (killed -> rerun the same command; `run_batch`
retries only failed/429 rows). If 429s persist, lower `--workers`.

## 4. What gets saved (parity - identical to the other models)

- **Trials:** `results/benchmark/trials/<model-slug>.jsonl` - one row per
  (item, arm, rep) = 1737 x 2 x 3 = 10,422 rows. Same schema as every other
  model, including: `t1_response/t1_choice/t1_outcome/t1_judge`,
  `t1_forced/t1_force_response/t1_force_choice/t1_outcome_first`,
  `first_time_unclear`, `t2_script/t2_message/t2_response/t2_choice/t2_outcome/t2_judge`,
  `t2_forced/t2_force_response/t2_outcome_first/t2_first_time_unclear`,
  `t2_regenerated/t2_forced_history`, `judge_prompt_sha` (must be
  `2001b3020d01fdd2`).
- **Taxonomy labels** append to `results/benchmark/honesty.jsonl` and
  `unclear_reasons.jsonl`, keyed by `utid = "<model>||<trial_id>"` (trial_id
  alone repeats across models - it encodes the item generator, not the
  model-under-test).
- **Metrics:** `metrics_v2.{csv,md}`, `cells_v2.csv`, `contrasts_v2.csv`.
- **Figures:** `results/benchmark/figures/*.png` (+ `taxonomy_summary.json`).
- **Dashboard:** `results/benchmark/pact_dashboard.html` (self-contained; publish
  via the Artifact flow to the existing URL to keep the same link).
- **HF build:** `results/benchmark/hf_results/` (trials.jsonl/parquet +
  leaderboard.csv + dataset card).

## 5. Verify parity (run after step 3, before metrics)

```bash
python - <<'PY'
import glob, os, json
RR2="2001b3020d01fdd2"; items={it["item_id"]:it for it in
  [json.loads(l) for l in open("results/benchmark/items_v1.jsonl",encoding='utf-8') if l.strip()]}
HELD={"comply","overcomply"}; f="results/benchmark/trials/<YOUR-MODEL>.jsonl"
n=t1rr2=clob=fc=fcmiss=pbrr2=pb=0
for l in open(f,encoding='utf-8'):
    l=l.strip()
    if not l: continue
    t=json.loads(l); n+=1
    if str(t.get("judge_prompt_sha"))==RR2: t1rr2+=1
    if t.get("t1_outcome")=="unclear" and t.get("t1_judge")=="llm" and t.get("t1_forced"): clob+=1
    it=items.get(t["item_id"])
    if t.get("t1_outcome") in HELD and it and it.get("t2_if_compliant") and t.get("t2_script")!="pushback": fcmiss+=1
    if t.get("t2_script")=="pushback":
        pb+=1
        if str(t.get("judge_prompt_sha"))==RR2: pbrr2+=1
print(f"rows={n} (want 10422)  t1_rerun2={t1rr2}/{n}  clobber={clob} (want 0)  "
      f"comply-missing-T2={fcmiss} (want 0)  t2_rerun2={pbrr2}/{pb}")
PY
```
Pass = 10,422 rows, t1/t2 100% rerun-2, clobber 0, comply-missing-T2 0.

## 7. Notes / gotchas learned the hard way

- **Reasoning judges need headroom too:** the gpt-oss extractor caps at 2048
  (proven 0 failures/156k); the honesty/unclear taxonomy judges cap at 8192
  (gpt-oss-as-judge returned empty at 512). These are internal - do not lower.
- **Honesty is scoped to BINDING violations only.** Non-binding "violations" are
  over-application and are excluded from axis 5.
- **Trivial agents** (`trivial:*`) are synthesized (no API), are the gameability
  floor, and are excluded from the taxonomy judges. Keep them in every release.
- **Background jobs get idle-killed** in some environments; all stages are
  resumable, so just rerun the same command to continue.
